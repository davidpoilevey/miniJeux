# Workspace ~/sitePerso — Jeux React

## Contexte
Ce workspace est dédié à la création de jeux et expériences interactives en React,
développés par passion et par plaisir. Pas de deadline, pas de ticket Jira — juste
l'inspiration du moment.

## Philosophie de travail
- La création se fait par étapes, guidée par l'inspiration
- Discuter d'abord, coder ensuite — mais un mini-proto vaut mieux qu'un long débat
- Un changement de direction en cours de route est une feature, pas un bug
- Rester léger : pas de sur-ingénierie, pas de code non demandé

## Processus attendu

### 1. Phase d'exploration
Quand une idée arrive (souvent en vrac), prendre le temps de la préciser ensemble :
poser des questions sur la mécanique, l'ambiance, l'expérience voulue, proposer
des angles. Ne pas foncer dans le code.

### 2. Phase de prototypage
- Commencer par un mini-proto : une mécanique, un composant, une idée validée
- Le proto n'a pas besoin d'être complet ni fonctionnel à 100% — il doit donner
  envie de continuer (ou de pivoter)
- Attendre le retour avant d'aller plus loin

### 3. Phase d'itération
- Si la direction change, embrasser le pivot sans chercher à "sauver" l'existant
- Ne jamais générer de grandes quantités de code non demandées

## Stack technique
- React (hooks, composants fonctionnels)
- Material UI pour l'interface
- Konva / react-konva pour le canvas et les éléments graphiques
- Animations basées sur setInterval (plus mobile-friendly que CSS animations complexes)
- Garder les dépendances légères — pas de lib lourde sans bonne raison

## Ton et style
On est en mode loisir ici : ton détendu, échanges détendus. On construit des jeux
pour le fun, autant que la conversation soit fun aussi. Une pointe d'humour ne
fait jamais de mal.

## À ne pas faire
- Générer un jeu complet d'un coup
- Anticiper des features non discutées
- Optimiser prématurément
- Proposer des architectures complexes avant que la mécanique de base soit validée
